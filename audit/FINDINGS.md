## CA-001：同步数据访问阻塞实时 Agent，当前已离线

- 严重度：P1
- 领域：架构、可靠性、性能
- 状态：已确认
- 置信度：高
- 可能性：高
- 影响：高
- 影响对象：全部纳管群、实时分析、通知阅读和后台任务
- 发布阻断：是
- 修复工作量：中到大

### 证据

- `src/review-base-gateway.js:35-62` 使用 `spawnSync` 和 `Atomics.wait`。
- `src/weekly-review-runtime.js:34-39` 在实时 Agent 同一事件循环调度同步网关任务。
- 当前运行证据：进程仍存在，健康状态已从“运行中”转为“离线/已告警”，心跳超过 10 分钟未更新。
- 本地证据：`.data/pending-batches` 有 14 个包含共 58 条消息的批次文件。

### 场景

飞书 CLI 或网络请求进入长超时和重试时，Node.js 主事件循环被同步子进程阻塞。事件消费者子进程可能仍连接，但父进程不能及时处理消息、心跳或停止信号。

### 建议与验收

- 把所有 CLI 调用改为异步子进程，或把审核/报告 Worker 拆到独立进程。
- 实时监听进程只负责接收、入队和轻量心跳。
- 验收：注入 60 秒飞书超时，心跳延迟不超过 2 个周期；连续 24 小时事件无丢失；队列深度与健康表一致。

### 反证尝试

Supervisor 可在进程退出后重启，健康监控也成功识别离线，但当前进程没有退出，因此 Supervisor 无法恢复该类“活着但阻塞”的故障。

## CA-002：自动写入和周期报告开关不生效

- 严重度：P1
- 领域：产品控制、AI 工具安全
- 状态：已确认
- 置信度：高
- 可能性：中
- 影响：高
- 发布阻断：是

### 证据

- `config/agent.config.json:225` 定义 `autoWriteVerified`。
- `src/review-workflow.js:204` 直接执行自动写入，没有读取该开关。
- `src/weekly-review-runtime.js:38-39` 始终调度周期报告，没有读取 `periodicReports.enabled`。
- 全仓引用搜索显示相关开关只存在于配置文件。
- `audit/logic-probes.test.js` 复现 `autoWriteVerified=false` 时仍发生写入调用。

### 场景

负责人以为已经关闭自动写入或周期报告，但 Agent 仍可继续修改成员档案、证据表和贡献表。

### 建议与验收

- 在动作入口和每个写入服务内双重检查开关，默认关闭。
- 增加运行时只读模式和紧急 kill switch。
- 验收：关闭开关后，模拟 auto_pass、人工确认和定时报告三条路径，飞书写调用均为 0。

### 反证尝试

当前配置值为 true，因此线上行为与配置表面一致；问题在于切换为 false 时不能形成安全边界。

## CA-003：问卷审核瞬时失败会永久退出处理队列

- 严重度：P1
- 领域：可靠性、数据完整性
- 状态：已确认
- 置信度：高
- 可能性：高
- 影响：中到高
- 发布阻断：是

### 证据

- `src/review-workflow.js:78-87` 只扫描空状态或显式历史状态。
- `src/review-workflow.js:215-218` 捕获模型/飞书错误后写入“处理失败”。
- 失败分支不创建负责人队列、不安排重试。
- 负向探针复现模型超时后来源记录永久变为“处理失败”。

### 建议与验收

- 增加独立审核任务表，状态至少包含待处理、处理中、待重试、永久失败、成功。
- 瞬时错误按有界退避重试，第 5 次才进入永久失败并私聊负责人。
- 验收：EOF、429、超时、格式错误均有明确分类和可恢复测试。

### 反证尝试

主消息分析链路已有可靠重试，但 v0.7 问卷工作流没有复用该机制。

## CA-004：人工审核状态机存在不可达和错误终态

- 严重度：P1
- 领域：产品流程、数据一致性
- 状态：已确认
- 置信度：高
- 可能性：高
- 影响：高
- 发布阻断：是

### 证据

- `src/v0.7-schema.js:26` 提供“标记共同贡献”和“调整项目”。
- `src/review-workflow.js:240` 的可执行状态不包含上述两项。
- `src/review-workflow.js:240-264` 把“暂缓”和“要求补充”直接标记为已执行。
- 负向探针复现两种行为。

### 建议与验收

- 建立显式状态转移表，不把暂缓和待补充视为终态。
- 调整项目、共同贡献、驳回、确认、修改后确认分别实现动作和审计记录。
- 只有动作成功后才能写 `已执行=true`；目标审核记录和来源问卷必须同步更新。
- 验收：每个状态至少一个成功、重复执行、失败恢复和非法转移测试。

### 反证尝试

人工可以手动修改飞书正式表作为临时补偿，但这会绕过自动写入日志和回滚证据链。

## CA-005：自报链接和无关旧证据可提升证据等级

- 严重度：P1
- 领域：AI 保障、组织公平性
- 状态：已确认
- 置信度：高
- 可能性：高
- 影响：高
- 发布阻断：是

### 证据

- `src/review-policy.js:62-66` 任意 artifact 即判 A，两个来源即判 B。
- `src/weekly-questionnaire.js:126-129` 成员填写的 URL 和附件计入独立来源。
- `src/review-workflow.js:53-67` 相关证据未按周期、审核状态或事实语义过滤。
- `src/review-workflow.js:184-186` 直接把相关记录数量和成员链接数量计入独立来源。
- 负向探针证明一条自报 URL 会得到 A。

### 建议与验收

- 自报 URL/附件最高只能是 C 级佐证，不能作为独立来源。
- A 级需要负责人确认或可校验的外部成果；B 级需要两个不同主体、不同消息或不同系统来源。
- 相关证据必须同时匹配成员、项目、周期、已确认状态和事实主题。
- 验收：自报链接、重复链接、旧项目证据、待审核证据均不能触发 A/B。

### 反证尝试

第二层 AI 有机会降级证据，但提示词不能替代确定性约束；模型也可能接受上游已经标为 A 的错误信号。

## CA-006：周报月报缺少独立二审并跨周期串队列

- 严重度：P1
- 领域：报告正确性、AI 保障
- 状态：已确认
- 置信度：高
- 可能性：高
- 影响：高
- 发布阻断：是

### 证据

- `src/periodic-reports.js:84-101` 审核队列没有周期字段过滤或审核 ID 关联。
- `src/periodic-reports.js:113-124` 只调用文字润色，随后可直接标记“AI已审核”。
- `src/review-analyzer.js:83-85` 只有 polish 调用，没有报告独立验证器。
- `src/v0.7-schema.js:24` 预留“周期报告审核”，运行代码未使用。
- 负向探针复现旧高风险队列进入当前周期报告。

### 建议与验收

- 队列项增加来源记录、周期开始/结束和报告 ID，并用精确关联查询。
- 报告执行确定性汇总、AI 整理、独立 AI 审核、风险分流四步。
- 未确认、高风险、跨来源冲突只进入负责人队列，不得标记已审核。
- 验收：跨周、跨月、跨项目、同名成员和旧队列负向测试全部隔离。

### 反证尝试

报告正文保留“已核验事实/成员自述”标签，这是有效控制，但不能阻止无关待审事项和风险等级污染。

## CA-007：自动写入日志与目标写入不是原子闭环

- 严重度：P1
- 领域：数据一致性、恢复
- 状态：设计风险
- 置信度：高
- 可能性：中
- 影响：高
- 发布阻断：是

### 证据

- `src/auto-write.js:80-93` 先创建日志，再创建目标，再更新日志。
- `src/auto-write.js:57-63` 日志收尾是独立网络写入。
- `src/auto-write.js:172-190` 回滚更新旧快照或直接删除目标，不比较当前版本。
- `src/review-base-gateway.js:80-83` 创建操作不重试，降低但未消除“响应丢失/进程终止”窗口。

### 场景

目标记录创建成功后，日志收尾 EOF 或进程终止。下次执行看到日志不是成功，可能再次创建。另一方面，人工修改过目标记录后执行回滚，会覆盖或删除后续合法修改。

### 建议与验收

- 目标表写入稳定 `operationId/factId`，重试前按该键对账。
- 新建结果没有 record ID 时不得标记成功。
- 回滚要求目标版本/内容仍与写入后快照一致，否则进入人工冲突处理。
- 验收：在目标成功、日志失败、响应丢失和进程崩溃点逐一注入故障，最终恰好一条记录。

### 反证尝试

稳定 operationId 和日志前置是良好基础，但当前缺少目标侧唯一约束和崩溃恢复对账。

## CA-008：Agent 用户身份权限显著超过最小需要

- 严重度：P1
- 领域：安全、权限
- 状态：已确认
- 置信度：高
- 可能性：中
- 影响：高
- 发布阻断：是

### 证据

- `src/review-base-gateway.js:65-66` 所有审核表读写使用 user 身份。
- `npm run doctor` 显示该身份除 Base 读写外，还拥有文档删除/移动、表和字段删除、群成员修改、消息撤回、审批写入等多类权限。报告不记录具体 token 或个人标识。

### 建议与验收

- 为 CloudAgent 建立独立应用服务身份和最小权限清单。
- 分离只读监听、运营中台写入、任务/日历命令三类身份。
- 默认拒绝删除、权限、群管理、审批和文档移动能力。
- 验收：撤销任一非必要权限不影响核心流程；越权动作返回明确拒绝并写安全日志。

### 反证尝试

当前代码没有调用大多数高危权限，但凭据一旦被滥用或命令边界出现缺陷，爆炸半径仍由授权范围决定。
